# 页脚弹簧光效设计

## 背景

用户希望把 21st.dev 的 Ruixen Gradient Footer 效果用于当前个人作品站，但不想替换现有页脚。新的交互要求是：原来的页脚保持不动，用户滑到原页脚后继续向下滚动，才出现彩色光效；往回滚动时，光效像弹簧一样收回。

当前项目是 Vue 3 + Vite，入口布局在 `src/App.vue`，全局样式在 `src/style.css`，组件放在 `src/components/`。现有页脚已经包含品牌、描述、GitHub、Email、即刻和版权信息，应继续保持可读和稳定。

附件提供的是 React + TypeScript 组件，依赖 shadcn/Tailwind 的项目约定。当前项目没有 React、Tailwind、shadcn 或 TypeScript，因此实现应转成 Vue 单文件组件和普通 CSS。

本次升级采用响应式双模式。桌面端恢复原有的连续尾部滚动交互：原页脚后保留一段滚动空间，光效随滚动连续升起和收回，不接管滚轮。移动端使用类似“上拉加载更多”的阈值揭层：正常状态下光效区域不占据页面高度并完整藏在视口下方；用户抵达页面底部后继续上拉时，原页脚整体向上移动并从其下方露出光效。未达到阈值时整体回弹，达到阈值后完整展开。两种模式完全展开后，各条状体都开始稳定、柔和的随机呼吸律动。

## 目标

- 保留 `App.vue` 里现有 `.footer` 的内容、结构和主要样式。
- 桌面端在原页脚后保留约 `38vh` 尾部空间，光效连续跟随正常页面滚动，不拦截滚轮。
- 移动端正常状态下页面结束于原页脚底部，不保留额外尾部空间。
- 移动端抵达底部后继续触控上拉，才把原页脚向上推并从它下方露出光效层。
- 使用 SVG 和 CSS/JavaScript，不新增 React、Tailwind、shadcn 或 TypeScript。
- 光效只作为装饰层，不承载任何关键信息。
- 支持 `prefers-reduced-motion: reduce` 降级。
- 修改后检查 UTF-8 和中文乱码问题。
- 桌面端使用连续滚动进度，不执行阈值吸附。
- 移动端触控拉起超过 `65%` 后吸附到完全展开，未达到阈值则回弹隐藏。
- 完全展开后，每根条状体以不同但可复现的周期、幅度和相位缓慢呼吸。

## 非目标

- 不把附件中的 `ruixen-gradient-footer.tsx` 原样复制到项目里。
- 不创建 `/components/ui`，因为这是 shadcn/React 结构，不符合当前 Vue 项目。
- 不改造现有 footer 链接、品牌、版权文字或信息架构。
- 不依赖浏览器原生 overscroll 橡皮筋行为。该行为在 Windows 和桌面 Chrome 上不稳定。
- 不让光效覆盖首屏、项目区或其它页面内容。
- 桌面端不注册需要 `preventDefault()` 的滚轮接管。
- 移动端不在页面尚未到达底部时拦截触控输入。
- 不使用每帧随机数驱动律动，避免条状体抖动和不可复现的视觉噪声。
- 移动端不通过透明遮罩伪装尾部空间；关闭状态下光效层不得增加文档的 `scrollHeight`。
- 不通过查询前一个兄弟节点并直接修改其行内样式来移动原页脚。

## 用户体验

桌面端正常滚动到现有页脚后，可以继续进入约 `38vh` 的尾部区域。光效根据尾部区域进入视口的比例连续升起；向上滚动离开时用弹簧追随平滑收回。滚轮始终保持浏览器原生滚动行为。

移动端正常滚动到现有页脚时，页面在原页脚底部结束，没有黑色空白尾巴，也没有可继续滚入的预留区域。抵达页面底部后继续触控上拉，原页脚随进度整体向上移动，藏在视口下方的彩色光效层同步从原页脚下方露出。

用户反向输入时，光带按输入量收回；停止在中途时根据阈值吸附到隐藏或完全展开，不会长期停留在半展开状态。

在减少动画偏好下，不运行弹簧循环和随机呼吸；输入结束后直接切换到对应端点。

移动端交互分为四个状态：

- `hidden`：组件收起，页面保持正常滚动。
- `pulling`：页面已经到达底部，继续向下滚轮或触控上拉会逐渐拉出组件。
- `expanded`：拉出进度超过 `65%` 并停止输入后，组件弹性吸附到完全展开。
- `collapsing`：完全展开后向上滚轮或触控下拉，组件先随输入收回；停止输入后按同一阈值决定恢复展开还是完全隐藏。

触控结束时进行吸附判断。低于 `65%` 的拉起进度回弹到 `hidden`，达到或超过 `65%` 则吸附到 `expanded`。只有端点吸附动画结束后才算状态切换完成。

当组件处于 `expanded` 时，九根条状体开始随机呼吸。随机参数在组件初始化时由条状体索引经过确定性公式生成，因此每根柱子的速度、幅度和相位不同，但刷新和重渲染时不会出现突变。律动保持低幅、慢速，不能改变整体中间高、两侧低的轮廓识别。

## 组件设计

修改现有组件：

- `src/components/FooterSpringGlow.vue`

组件职责：

- 通过默认 slot 包裹并渲染原 footer。
- 桌面模式下在原 footer 后生成约 `38vh` 的普通文档流尾部区域。
- 移动模式下组件根节点只占原 footer 的正常布局高度，不增加尾部滚动空间。
- 渲染固定藏在视口下方的 SVG 光效层。
- 根据页底状态和滚轮、触控输入计算拉起进度。
- 用 `requestAnimationFrame`、速度值和阻尼参数让实际进度追随目标进度。
- 在组件卸载时移除事件监听并取消动画帧。
- 监听 `prefers-reduced-motion`，必要时关闭动态追随。
- 桌面模式根据尾部区域位置计算连续滚动进度。
- 移动模式只在页面抵达底部且用户继续触控上拉时接管触控拖动。
- 管理 `hidden`、`pulling`、`expanded`、`collapsing` 四个状态。
- 在完全展开时启动条状体随机呼吸，离开展开状态时停止呼吸。

`App.vue` 接入方式：

- 保持现有 `<footer class="footer">...</footer>` 的内容和类名不变。
- 用 `<FooterSpringGlow>` 包裹原 footer，并把 footer 作为默认 slot 内容。
- 根 `.site` 和 `main` 的 flex 布局保持现状。

建议 props：

- `desktopTailHeight`：桌面端尾部滚动空间高度，默认 `38vh`。
- `revealHeight`：桌面端光效完整展开高度，默认 `min(58vh, 520px)`。
- `mobileRevealHeight`：移动端完整展开高度，默认 `min(46vh, 360px)`。
- `snapThreshold`：端点吸附阈值，默认 `0.65`。

首版可以只使用默认值，不暴露复杂调参。

## 光效实现

光带延续 Ruixen Gradient Footer 的核心视觉：多个模糊矩形柱组合成中间高、两侧低的彩色光幕。Vue 组件中保留这些稳定常量：

- viewBox 宽高：`1271 x 599`
- stops：暗红、蓝、浅蓝、近白、黄、红橙、品红、透明粉
- bars：默认 9
- blur：默认 15
- peak：默认 0.98
- valley：默认 0.55

`bellHeights` 作为普通 JS 函数保留，用于生成每个柱子的高度。SVG 使用唯一 id，避免同页多个渐变或滤镜冲突。

## 滚动与弹簧算法

组件先判断页面是否抵达底部，再把被接管的输入增量除以实际光效层高度，归一化为 `0–1` 的拉起进度。关闭状态没有额外文档高度，因此页底检测以原 footer 的正常底部为准。

实际显示进度使用弹簧追随：

- 保存 `current`、`target`、`velocity`。
- 每帧计算 `force = (target - current) * stiffness`。
- `velocity = (velocity + force) * damping`。
- `current += velocity`。
- 当 `current` 和 `target` 足够接近时停止动画帧。

光带样式由 CSS 变量驱动：

- `--footer-glow-progress`
- `--footer-glow-opacity`
- `--footer-glow-lift`

主要变换使用 `transform: translate3d(...)`：页脚内容层向上平移，光效揭层从视口下方向上平移，避免频繁修改布局属性。

### 上拉揭层布局

`FooterSpringGlow` 使用三层结构：

- 根容器：参与正常文档流；桌面端包含 footer 与尾部空间，移动端高度仅由 slot 中原 footer 决定。
- 页脚内容层：承载默认 slot；按 `progress × revealHeight` 向上平移。
- 光效揭层：固定在视口底部，关闭时整体位于视口下方；按同一进度向上平移并露出。

移动端进度为 `0` 时，页脚内容层没有位移，光效揭层完全位于视口下方，页面高度与未接入组件时一致。进度为 `1` 时，页脚内容层向上移动完整光效高度，光效揭层完整占据视口底部。两个图层必须使用同一个进度变量，避免页脚和光效之间出现裂缝或重叠跳变。

桌面端页脚内容层始终不移动。根容器在 footer 后渲染普通文档流尾部区域；固定光效层根据这段尾部进入视口的比例，从视口底部连续升起。桌面端的尾部空间只用于正常滚动，不使用阈值状态机。

光效揭层使用 `position: fixed`，因此本身不参与布局。桌面端只有独立的尾部占位层增加 `scrollHeight`；移动端隐藏该占位层，因此关闭状态不增加文档高度。组件卸载或离开交互范围时恢复关闭端点。

### 桌面连续滚动

使用 `matchMedia('(max-width: 720px)')` 区分模式。桌面模式监听被动 `scroll` 和 `resize`：

- 根据尾部占位层的 `getBoundingClientRect()` 计算 `visibleProgress`。
- 目标进度从 `0` 连续变化到 `1`，实际进度继续使用弹簧追随。
- 不监听或接管 `wheel`，不调用 `preventDefault()`。
- 滚动到尾部最底端并稳定后，将交互状态视为 `expanded`，启用随机呼吸。
- 向上滚动离开尾部区域后，目标进度回落到 `0`。

### 移动端输入接管与吸附

页面未到达底部时不拦截触控输入。页面到达底部后：

- 触控上拉增加组件展开进度，并阻止这部分已经用于上推原页脚的默认滚动。
- 完全展开后，继续向下输入不再累积进度。
- 向上滚轮或触控下拉减少展开进度；组件完全隐藏后，后续向上输入恢复页面正常滚动。
- `touch` 输入在 `touchend` 或 `touchcancel` 时结束手势。
- 输入结束时，以 `0.65` 为吸附分界，将目标进度设为 `0` 或 `1`，沿用弹簧积分器完成回弹。

事件监听需要满足浏览器约束：需要调用 `preventDefault()` 的 `touchmove` 监听不得使用 `passive: true`；普通 `scroll`、`resize` 监听仍保持被动。触控逻辑记录最后一个触点的纵坐标，以相邻移动差值更新进度，并避免多指手势误触发。

### 模式切换

监听断点媒体查询变化。跨越 `720px` 时：

- 停止正在运行的弹簧帧并清除触控状态。
- 将进度、速度、目标值和交互状态重置到关闭端点。
- 重新测量揭层高度和桌面尾部位置。
- 只启用当前模式需要的逻辑；桌面端不保留非被动触控接管，移动端不使用桌面尾部进度。

### 随机呼吸

每个条状体预先获得一组确定性参数：

- 幅度约为自身基础高度的 `2%–7%`。
- 周期约为 `2.8–5.2s`。
- 相位错开，避免九根柱体同时到达波峰。
- 使用平滑正弦或等价缓动函数，不在动画帧中调用 `Math.random()`。

呼吸变换只作用于单根条状体的纵向尺度，并以底部为变换原点。整体展开进度仍由外层光带控制，两层变换互不干扰。只有状态稳定为 `expanded` 时添加律动类；进入 `pulling` 或 `collapsing` 后立即移除。

## 响应式与性能

桌面端：

- 原 footer 后增加约 `38vh` 尾部滚动空间。
- 光效揭层完整高度默认不超过 `520px`，并固定在视口底部。
- 光效揭层使用 `pointer-events: none`。
- SVG 不捕获焦点，不影响返回顶部按钮和 footer 链接。

移动端：

- 关闭状态同样不增加尾部高度。
- 光效揭层完整高度不超过 `360px`。
- 光带透明度降低，避免完整展开时视觉过重。
- 不改变现有 footer 在窄屏下的换行规则。

性能：

- 不使用 canvas 或 WebGL。
- 只在滚动目标变化或弹簧尚未稳定时运行动画帧。
- `scroll` 和 `resize` 监听使用 `{ passive: true }`；移动端需要阻止默认行为的 `touchmove` 使用非被动监听。
- 端点吸附沿用单一 `requestAnimationFrame` 弹簧循环，不为每根条状体建立 JavaScript 动画循环。
- 随机呼吸使用 CSS 动画和每根柱体的 CSS 自定义属性实现。
- 只在可能接管输入时执行轻量的页面底部判断。

## 可访问性

- 光效根节点使用 `aria-hidden="true"`。
- 光效揭层不包含可聚焦元素，slot 中原 footer 的链接保持正常交互。
- 减少动画偏好下关闭弹簧动画。
- 减少动画偏好下关闭随机呼吸，并把吸附切换为无振荡的端点更新。
- 原 footer 链接保持原有可访问性和键盘访问行为。

## 自检

- 设计明确保留原 footer，不替换现有页脚。
- 设计明确桌面端使用普通尾部滚动区，移动端关闭状态没有额外尾部滚动区。
- 设计范围聚焦在 `App.vue` 和新增组件，没有扩大到首页内容或其它页面。
- 实现路径符合当前 Vue 3 + Vite 项目结构。
- 包含响应式、性能、减少动画偏好、可访问性和编码验证要求。
- 没有未定需求、空白项或互相矛盾的章节。
- 移动端阈值明确为 `65%`，触控结束时立即判断吸附端点。
- 只有移动端触控输入会在页面底部被接管；桌面滚轮始终保持原生滚动。
- 随机呼吸采用确定性参数和 CSS 动画，不增加持续的 JavaScript 多柱动画循环。
- 原页脚通过 slot 被组件包裹并整体上移，光效从它下方露出；没有直接操作兄弟 DOM。
