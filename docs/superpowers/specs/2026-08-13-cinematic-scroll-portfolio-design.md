# 电影式滚动作品站设计

## 目标

把现有个人作品站升级为一支可滚动的交互短片，首先展示大笨钟的个人审美与前端技术能力。整体气质采用“数字艺术展”，动效强度保持明显实验性，但不妨碍访客阅读内容、查看作品或使用普通导航。

本次设计不以增加更多零散特效为目标。现有液态金属背景、3D 金属方块、Canvas 字体、作品书页和页脚弹簧光效将被重新分配到不同章节，形成有起承转合的统一叙事。

## 设计原则

- 每个章节只有一个主视觉和一个主动作，其他元素仅作轻微响应。
- 滚动推进主线，点击探索细节；访客不需要学习特殊操作才能浏览完整内容。
- 真实作品是首页的视觉核心，装饰效果用于强化作品表达。
- 桌面端提供完整体验；移动端减少 3D、模糊、粒子和长距离位移，不机械复制桌面动画。
- 支持 `prefers-reduced-motion`；弱性能设备可进入静态或轻动效版本。
- 不默认播放声音。若未来增加环境音，必须由访客主动开启并提供清晰的关闭入口。

## 六章叙事结构

### 01 开场：身份建立

保留当前液态金属背景和 3D 金属方块。首屏标题不再一次性完整出现，而是随着首段滚动从巨大字形遮罩中揭示。章节结束时出现固定格式的编号和标题，建立后续叙事规则。

目标是在约五秒内让访客记住“大笨钟 / DEV”的身份、荧光绿品牌色和金属数字艺术气质。

### 02 宣言：创作观

将当前四项能力列表压缩为三条更有性格的创作原则，例如“从真实摩擦开始”“让技术服务维护成本”“默认把数据留给用户”。每条宣言随滚动占据主要视野，并短暂穿插相关作品图像。

这一章回答“为什么这样做”，避免继续罗列常见技术标签。

### 03 作品首映：真实作品

将三个作品从重复卡片改为三个连续的全屏场景。每个场景包括：

- 项目编号、名称和一句核心主张；
- 项目独有的章节色彩；
- 真实手机截图或设备模型；
- 一个主要入场动作；
- 通往现有项目详情页的明确入口。

项目切换采用换幕逻辑：前一个场景收束后再引入下一个场景，不让多个重型动画同时运行。作品数据继续来自 `src/data/projects.js`。

### 04 互动实验室：可玩的技术样本

新增 `/lab` 页面，集中展示可独立操作的视觉实验。首批仅包含现有能力可以支撑的四项：

- 液态材质；
- 3D 金属方块；
- Canvas 字体；
- 磁吸按钮。

每个实验提供少量有意义的参数、暂停和恢复默认值。实验室的目的不是成为完整设计工具，而是让访客直接感受到视觉与代码之间的关系。

### 05 幕后：制作过程

把现有四步流程改成横向制作时间线，展示从发现问题、设计、构建到迭代的过程。时间线可以穿插草图、代码片段和版本节点，但首期只使用已有或真实可提供的内容，不制造虚构数据。

桌面端通过滚动驱动横向推进；移动端改为自然纵向时间线，避免强制横向手势。

### 06 片尾：联系装置

保留现有页脚弹簧光效，并将其改造成整段体验的收束。访客靠近联系区域时，光点逐渐汇聚，标题重组为“LET'S BUILD”，随后显露邮箱和 GitHub 入口。

关键联系方式始终可读取、可聚焦，不能依赖动画完成后才能访问。

## 导航与章节 HUD

桌面端增加低调的章节 HUD，显示类似 `03 / 06 — REAL WORK` 的当前状态。HUD 由已有的区块观察逻辑驱动，可点击跳转到对应章节。移动端仅显示进度和当前章节编号，避免占用横向空间。

现有顶部导航继续保留，确保访客能够直接访问作品、关于和实验室。自定义光标只在支持精确指针的设备上、且仅进入可交互区域时改变形态，不全程追踪鼠标。

## 组件与数据边界

`HomeView.vue` 负责章节组合和页面级状态，不继续承载每个动画的内部实现。建议增加以下组件：

- `CinematicChapter`：统一章节容器、编号、进入状态与静态降级接口；
- `ChapterHud`：呈现当前章节和跳转入口；
- `ProjectPremiere`：渲染单个项目的全屏首映场景；
- `MotionLab`：承载单个实验的预览、参数、暂停与重置逻辑。

`projects.js` 在现有字段上增加展示字段：

- `chapterColor`：项目场景主色；
- `statement`：首映场景的一句核心主张；
- `motionPreset`：从有限的预设动画中选择一种，不在数据文件中存放任意脚本。

组件应保持清晰边界：页面传入内容和预设，组件内部负责渲染与动画生命周期。现有项目详情路由和数据读取方式不改变。

## 动效与性能规则

- 普通转场控制在约 `400–800ms`，关键镜头可以更长，但不得阻塞滚动。
- 允许短暂的视觉吸附，不使用强制滚动锁定或滚轮劫持。
- 滚动状态统一通过 `requestAnimationFrame` 更新，避免每个组件各自注册高频滚动处理器。
- 不在屏幕附近的 Three.js、Canvas 和材质动画暂停或降低刷新频率。
- 动画优先使用 `transform` 和 `opacity`，谨慎使用大面积滤镜与持续模糊。
- 根据屏幕宽度、`prefers-reduced-motion` 和基础性能探测选择完整、轻量或静态模式。
- 静态模式保留完整内容、层级、链接和章节顺序，只移除非必要运动。

## 异常与降级

- WebGL 或 Canvas 初始化失败时显示对应章节的静态海报，不留下空白区域。
- 项目图片加载失败时显示项目名称、主色和替代文字组成的封面。
- `IntersectionObserver` 不可用时采用滚动位置计算当前章节，或退化为普通顺序页面。
- 实验参数发生无效值时回到最近的合法值；“恢复默认值”始终可用。
- JavaScript 未完成初始化前，页面的正文、项目链接和联系方式仍可阅读与访问。

## 分阶段实施

### 第一阶段：作品首映

先完成 `ProjectPremiere`、章节 HUD 和三个项目场景，并复用现有截图、路由与项目数据。这一阶段能以最小范围产生最大的视觉提升，也能验证滚动章节模型和移动端降级策略。

### 第二阶段：互动实验室

增加 `/lab` 路由和首批四个实验。优先复用现有视觉组件，将可调参数限制在清晰、稳定的范围内。

### 第三阶段：统一电影叙事

依次改造首屏揭幕、创作宣言、制作时间线和片尾联系装置，最后统一六章节奏，并完成性能、无障碍和多设备调整。

## 验证标准

- 桌面端完整滚动一遍时，各章节顺序正确，转场没有明显跳动或多个主效果同时争抢注意力。
- 手机端可以自然纵向浏览，不出现横向溢出、滚动锁死或必须依靠悬停才能访问的内容。
- 三个项目的详情入口均可通过鼠标、触摸和键盘访问，浏览器前进与后退行为正常。
- `prefers-reduced-motion: reduce` 下不存在持续位移、视差和强制吸附，所有信息仍完整呈现。
- WebGL、Canvas 或图片加载失败时出现可读的静态替代内容。
- 离开可视区域的重型动画能够暂停或显著降频。
- 修改后的 Vue、JavaScript、CSS 和 Markdown 文件均可按 UTF-8 正常读取，中文不存在乱码。

## 暂不包含

- 默认背景音乐、自动播放视频或必须开启声音才能理解的内容；
- CMS、账号系统、访客评论或云端实验参数保存；
- 为每个项目编写完全不同且无法复用的动画引擎；
- 在第一阶段全面重写关于页和项目详情页；
- 为视觉效果引入新的大型动画框架。
