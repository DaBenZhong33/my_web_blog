# 首页结构与交互改版设计

## 背景

当前首页已经完成了 Framer 模板风格迁移：黑白高反差网格、酸绿色强调、AI 人物主视觉、能力列表、浅色故事区、作品卡、流程区和底部 CTA 都已经存在。

这次改版的目标不是更换视觉风格，而是把页面结构规划得更清楚，并增加几处能提升探索感的交互。用户已确认采用「叙事导向」路线：先讲清楚大笨钟是谁、在做什么、为什么值得继续看，再引导到作品、流程和联系入口。

## 目标

- 首页从“一段段堆叠”调整为有明确浏览路径的叙事结构。
- 增加可感知的交互，但避免复杂到影响维护和移动端体验。
- 保留现有 Framer 模板视觉语言：巨型标题、酸绿色角标、噪点、网格、直角卡片、黑白反差。
- 改善代码结构，避免 `HomeView.vue` 继续膨胀。

## 非目标

- 不重做关于页和项目详情页的整体设计。
- 不新增后端、CMS 或远程数据接口。
- 不做命令面板、复杂页面路由动画或全站搜索。
- 不引入大型动画库；优先使用 Vue、CSS 和浏览器原生 API。

## 信息架构

首页顺序调整为：

1. `Intro`：首屏身份、定位、主视觉、状态终端和主要 CTA。
2. `Build`：做什么，展示能力模块。
3. `Story`：关于大笨钟的产品原则、当前状态和指标。
4. `Work`：作品展示，支持快速预览。
5. `Process`：做产品流程，先强化层级，不做复杂联动。
6. `Contact`：底部 CTA，提供邮件、GitHub 和回到作品入口。

## 交互范围

### 章节导航与滚动进度

新增一个章节轨道，展示 `Intro / Build / Story / Work / Process / Contact`。

- 桌面端：放在页面左侧或内容容器边缘，滚动时固定显示。
- 移动端：降级为横向滚动 pill 导航，避免遮挡正文。
- 当前章节通过 `IntersectionObserver` 更新。
- 顶部或轨道内显示页面滚动进度。
- 点击章节项平滑滚动到对应区块。

### 首屏状态终端

把现在的浮动状态卡改成一个更明确的状态终端。

内容示例：

- `CURRENT BUILD`：正在维护 3 个产品。
- `STACK ONLINE`：Vue 3、SwiftUI、Flutter、Kotlin。
- `DATA MODE`：Local-first / private by default。
- `NEXT SHIP`：继续迭代作品详情页。

交互：

- 状态项可点击切换高亮说明。
- 桌面端可保留轻微浮动或扫描线效果。
- 移动端改为普通卡片，避免遮挡首屏标题。
- 不使用长时间强制自动播放，减少分散注意力。

### 作品快速预览

作品卡仍然可以进入详情页，但增加快速预览层。

- 桌面端：hover 或 focus 时展示预览面板。
- 移动端：点击“预览”按钮展开卡片内详情。
- 预览内容包含：项目简介、核心功能、技术栈、截图标签、详情入口。
- 预览必须支持键盘 focus，不只依赖鼠标 hover。

## 组件结构

为控制 `HomeView.vue` 体积，建议新增三个轻量组件：

- `src/components/SectionRail.vue`
  - 输入：`sections`、`activeSection`、`progress`
  - 输出：点击章节时触发 `navigate`
  - 责任：展示章节导航和滚动进度。

- `src/components/StatusTerminal.vue`
  - 输入：`items`
  - 内部状态：当前选中状态项
  - 责任：首屏状态终端展示和状态切换。

- `src/components/ProjectPreviewCard.vue`
  - 输入：`project`、`image`
  - 内部状态：预览是否展开
  - 责任：作品卡视觉、快速预览和详情入口。

`HomeView.vue` 保留页面级数据和布局编排：章节数组、能力数组、指标数组、流程数组和项目图片映射。

## 数据流

- 首页定义 `sections` 数组，包含 `id`、`label`、`title`。
- `HomeView.vue` 在 `onMounted` 中注册 `IntersectionObserver`，根据区块进入视口更新 `activeSection`。
- 滚动监听只负责计算 `progress`，使用 `requestAnimationFrame` 节流。
- `SectionRail` 点击章节后调用 `scrollIntoView` 或路由 hash 滚动。
- `ProjectPreviewCard` 直接使用 `projects.js` 中已有项目数据，不复制项目内容。

## 可访问性与响应式

- 所有可点击卡片和按钮必须有可见 focus 状态。
- 作品预览不能只靠 hover；移动端和键盘用户必须能打开。
- 滚动进度和视觉扫描线只是增强效果，不承载唯一信息。
- 尊重 `prefers-reduced-motion: reduce`，关闭浮动、扫描线和非必要动画。
- 移动端首屏不让状态终端覆盖标题或 CTA。

## 错误处理与边界

- 如果项目图片加载失败，卡片仍显示渐变背景和项目信息。
- 如果 `IntersectionObserver` 不可用，章节导航默认高亮 `Intro`，点击仍可滚动。
- 如果项目数据缺少链接，详情入口仍使用本地路由 `/project/:id`。
- 预览展开状态不写入 URL，避免浏览器返回行为变复杂。

## 测试与验证

实现后至少运行：

- `npm run build`
- UTF-8 严格读取改动文件。
- 搜索常见 UTF-8 乱码标记，确认没有误编码文本。
- 桌面视口检查：首屏、章节轨道、作品预览、底部 CTA。
- 移动视口检查：首屏标题不重叠、章节导航可横向滑动、作品预览可点击展开。
- 浏览器控制台检查无运行错误。

## 实施顺序

1. 抽出 `SectionRail.vue`，在首页接入章节数组、active 状态和滚动进度。
2. 抽出 `StatusTerminal.vue`，替换首屏浮动状态卡。
3. 抽出 `ProjectPreviewCard.vue`，替换作品卡并加入预览交互。
4. 调整首页区块 id、文案层级和响应式布局。
5. 运行构建、编码检查和桌面/移动视觉验证。

## 自检

- 没有遗留占位任务标记或未定需求。
- 范围限定在首页结构和三处交互增强。
- 组件职责清晰，避免继续堆大 `HomeView.vue`。
- 移动端、键盘访问和减少动画偏好都有对应要求。
