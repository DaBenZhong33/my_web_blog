# 首页 Three.js 金属立方体设计

## 背景

首页首屏当前在右侧使用 `/template-assets/hero-ai.png` 作为主视觉。用户希望移除这张图片，改为一个具有金属质感的 3D 正方体：默认自转，鼠标悬停时六个面向四周展开，形成类似爆炸或解构的效果；鼠标移开后恢复为完整正方体，并恢复较快自转。

当前项目是 Vue 3 + Vite，首页主体在 `src/views/HomeView.vue`。项目已经有滚动 reveal、磁吸按钮、作品卡 3D 倾斜和首页结构验证脚本。用户已确认可以新增 `Three.js` 依赖。

## 已确认方向

- 展开方式：戏剧化碎裂。六个面分离距离更远，并带少量不同方向的旋转，表现更强的解构和冲击感。
- 金属质感：拉丝银色。整体克制、工业感明确，不使用过亮的高反射铬面。
- 技术方案：`Three.js + 6 个独立金属面片`。默认把 6 个面片拼成正方体，hover 时把每个面片插值到展开状态。

## 目标

- 用 Three.js 立方体替换首屏 `hero-ai.png`。
- 保留当前首页黑底网格、噪点、硬边框和荧光黄点缀的视觉语言。
- 默认状态下立方体持续自转，作为首页右侧主视觉。
- hover 状态下六个面向外展开，自转速度明显变慢。
- 鼠标移开后快速恢复为完整正方体，自转速度恢复。
- 移动端、减少动画偏好和 WebGL 初始化失败时都有可用降级。
- 修改后保持 UTF-8 编码，并检查中文文本是否出现乱码。

## 非目标

- 不重做首页信息架构、标题文案、按钮文案或其它页面。
- 不把首屏改成完整的 3D 场景展示页。
- 不添加复杂后期处理、HDR 环境贴图管线、物理粒子或音效。
- 不引入 React、Tailwind 或 UI 组件库。
- 不保留 `hero-ai.png` 作为首屏主视觉。

## 方案比较

### 方案 A：Three.js + 6 个独立金属面片

这是推荐并已确认的方案。每个面使用独立 `PlaneGeometry` 和金属材质，闭合状态时拼成一个正方体，展开状态时按各自法线方向远离中心，并叠加轻微旋转。优点是动画控制精确，hover 展开自然，恢复状态清晰。缺点是需要手动维护 6 个面的目标姿态。

### 方案 B：Three.js + BoxGeometry 切换面片

默认用完整 `BoxGeometry`，hover 时切换为 6 个独立面片。优点是默认状态最接近真实立方体；缺点是切换瞬间可能出现视觉跳变，实现复杂度更高，不适合当前需求。

### 方案 C：CSS 3D 面片

用 DOM 和 CSS `transform-style: preserve-3d` 模拟立方体。优点是轻量且无依赖；缺点是金属光照和空间真实感较弱。由于用户已接受 Three.js，此方案只作为 WebGL 失败时的静态 fallback 思路。

## 交互设计

桌面端默认展示一个拉丝银色金属正方体。它位于原 `hero-ai.png` 的视觉区域，保持右侧主视觉的重量，不遮挡标题、按钮和底部 `大笨钟+` wordmark。默认自转速度应明显可见但不刺眼。

鼠标进入立方体交互区域后，组件进入展开状态：

- 六个面向各自外侧移动，距离比标准 exploded view 更大。
- 每个面有少量不同的旋转角，形成戏剧化碎裂感。
- 中心可保留弱荧光黄核心或薄光晕，呼应首页 accent 色，但不能变成主要视觉。
- 整体自转速度降低，让用户能看清分离后的面片。
- 鼠标移开后，面片快速回到闭合姿态并重新组成完整正方体，自转速度恢复。

移动端没有稳定 hover，默认只展示自转立方体。支持触摸的设备可以通过点击或按下触发一次短暂展开，停留后自动恢复。手机端展开距离要缩小，避免面片碰到首屏文字或超出视觉容器。

## 组件设计

新增 `src/components/HeroMetalCube.vue`，只负责 Three.js 场景和交互状态。`HomeView.vue` 只负责布局，把现有 `hero-frame > img.hero-person` 替换成该组件。

`HeroMetalCube.vue` 内部职责：

- 创建 `scene`、`camera`、`WebGLRenderer`。
- 创建环境光、方向光和用于边缘高光的辅助方向光。
- 创建 6 个 `PlaneGeometry` 面片，并保存每个面的闭合状态和展开状态。
- 使用 `MeshStandardMaterial` 或同类 PBR 材质，设置较高 `metalness`、中等 `roughness`，并用程序化 canvas 纹理模拟细微拉丝纹理。
- 使用 `requestAnimationFrame` 执行动画循环。
- 根据 hover/touch 状态对面片位置、旋转和整体自转速度做平滑插值。
- 监听容器尺寸变化并更新 renderer 尺寸和 camera aspect。
- 组件卸载时清理事件、动画帧、renderer、geometry、material 和 texture。

`HomeView.vue` 保留当前 `heroVisual` 滚动位移逻辑。`hero-visual` 和 `hero-frame` 的尺寸约束继续作为主视觉布局基础，减少对其它首屏元素的影响。

## 材质与视觉细节

材质方向为拉丝银色金属：

- 主色使用银灰、深灰和白色高光。
- 拉丝纹理使用细线条噪声，不依赖额外图片资源。
- 光照使用低强度环境光加一到两个方向光，制造边缘高光。
- 边缘可加非常轻的荧光黄反射或中心光晕，强度要低于按钮和标题下划线。
- canvas 背景透明，让现有首页网格和噪点继续作为背景。

立方体不使用过度圆角，不使用漂浮卡片容器，不添加装饰性渐变圆球。视觉重点是金属面片、空间展开和现有首屏内容的配合。

## 可访问性与降级

- `prefers-reduced-motion: reduce` 下禁用持续自转和展开动画，只显示静态闭合立方体。
- WebGL 初始化失败时显示 CSS 静态 fallback：一个由渐变和边框模拟的金属立方体或等距金属方块，不让首屏右侧空白。
- canvas 标记为装饰性视觉，使用合适的 `aria-hidden`，不把核心信息放在 3D 视觉里。
- 触摸触发展开只是增强效果，不作为必要操作路径。
- 交互区域应足够大，但不能覆盖左侧标题和按钮。

## 响应式

桌面端保持右侧大尺寸主视觉，立方体在原图片区域居中偏右。平板端跟随现有单列布局居中。手机端缩小 canvas 和立方体尺寸，减少展开距离，并确保 `hero-wordmark`、标题、按钮和立方体不发生重叠。

建议通过 CSS 变量或组件内部断点控制：

- canvas 容器高度
- camera 距离
- 立方体尺寸
- 展开距离
- 触摸展开停留时间

- `npm run verify:homepage`
- `npm run build`
- 使用 UTF-8 读取修改过的 Vue、CSS、脚本和 JSON 文件
- 搜索常见乱码标记，确认没有错误编码文本

浏览器人工检查：

- 桌面首屏不再显示 `hero-ai.png`。
- Three.js canvas 非空，默认显示金属立方体并自转。
- hover 后六个面确实向四周展开，自转速度变慢。
- 鼠标移开后面片恢复成完整正方体，自转速度恢复。
- 手机尺寸下立方体不遮挡标题、按钮和 wordmark。
- `prefers-reduced-motion: reduce` 下视觉静态且页面可用。
- WebGL 失败 fallback 不出现空白。
