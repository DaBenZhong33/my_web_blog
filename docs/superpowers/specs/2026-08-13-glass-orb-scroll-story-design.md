# 首页玻璃球滚动叙事设计

## 目标

用一个由滚动驱动的 3D 玻璃球替换首页首屏现有的金属立方体。它负责把访客从暗色英雄区带入“我能做什么”的能力区：玻璃球聚焦、碎裂、镜头穿越碎片，再以斜向电影切口显现内容。

该段动效以沉浸式节奏占用约四屏高度，但不锁定滚动，也不阻止用户快速掠过。

## 已确认的创意方向

采用“穿透式开场”和“破碎成转场”的组合：

- 玻璃球位于首屏视觉区中心，是唯一的 3D 主体。
- 碎裂后，镜头沿一枚主碎片的方向推进，其他碎片向两侧形成短暂的纵深隧道。
- 镜头穿出时，碎片在画面中构成一道由左下至右上的斜向切口。
- 首屏暗场经切口退去，能力区从右侧以浅色背景、标题和第一行能力内容逐层显影。
- 首个被揭示的内容是“我能做什么”，不是个人介绍或项目列表。

## 实现方案

采用混合式实现：Three.js 只绘制玻璃球、碎片和镜头运动；页面内容继续由 Vue 与 CSS 排版和显影。

### 组件

新增 `HeroGlassOrbStory.vue`，替代 `HeroMetalCube.vue` 在 `HomeView.vue` 中的使用。组件职责：

- 创建并销毁 Three.js 场景、相机、渲染器、球体和碎片。
- 根据组件容器的滚动位置计算 0 到 1 的连续进度。
- 将进度映射为球体材质、裂纹强度、碎片变换和镜头位置。
- 输出 CSS 自定义属性，供首屏、过渡遮罩和能力区的 DOM 动画使用。
- 侦听尺寸变化、可见性与 `prefers-reduced-motion`，并妥善释放 WebGL 资源。

`HomeView.vue` 负责页面叙事结构：将英雄区和能力区包在同一个滚动故事容器内；保留现有的网格、液态金属背景与首屏文案；能力列表仍使用现有数据和卡片结构。

### 场景资产与材质

- 玻璃球使用 `MeshPhysicalMaterial`，低粗糙度、高透射与轻微色散；环境反射延续现有黑、银、荧光绿的色彩。
- 球体外层附加细裂纹纹理或线框裂纹，避免高密度真实破碎模拟。
- 爆裂后使用 36～48 个预生成的低多边形碎片；每块碎片有固定的种子、旋转轴、速度和结束位置，以保证同一滚动位置稳定可复现。
- 一枚主碎片承担视觉引导；相机朝其路径推进，但不会产生晕动感明显的急转。

## 滚动时间线

| 区间 | 画面 | 内容层 |
| --- | --- | --- |
| 0.00～0.23 | 玻璃球悬浮呼吸，环境高光缓慢移动。 | 首屏文案完整可读。 |
| 0.23～0.45 | 裂纹由中心扩散，荧光绿核心短暂增强。 | 文案略微退后，不改变布局。 |
| 0.45～0.75 | 球体碎裂；碎片向两侧旋转飞散，相机沿主碎片推进。 | 首屏文案淡出；暗场保持。 |
| 0.75～1.00 | 主碎片拉开斜向切口，相机穿出碎片。 | 浅色能力区从右侧显影；标题、说明、首行能力项按层进入。 |

故事容器在桌面端高度约为 `400vh`。滚动位置连续映射到时间线，用户的惯性、快速滚动和锚点跳转都可自然工作。

## 响应式、无障碍与降级

- 宽度低于 720px 时，故事容器缩短为约两屏；碎片限制为 16～20 块，取消复杂景深与长距离镜头推进。
- `prefers-reduced-motion: reduce` 时，不创建持续渲染循环；展示静态玻璃球和能力区，内容立即可见。
- WebGL 创建失败时，显示 CSS 制作的静态玻璃球与斜向渐变过渡，不隐藏任何文本或能力内容。
- 3D 画布设为装饰性，使用 `aria-hidden="true"`；页面内容维持原本的语义结构和键盘可达性。
- 渲染像素比与帧率按现有组件的性能上限控制，页面不可见时暂停动画。

## 验收标准

- 桌面端滚动四屏内可完整经历“聚焦、碎裂、穿透、能力区显影”。
- 玻璃球替代现有金属立方体，首屏文字、网格背景和液态金属背景保留且层级正确。
- 第一段显现的正文是能力区；内容不被 Canvas 覆盖，链接和按钮可用。
- 移动端无明显掉帧，且以更短的叙事完成过渡。
- 减少动态与无 WebGL 情况下，所有内容仍可读取、浏览与操作。
- 组件卸载时释放渲染器、几何体、材质、纹理和事件监听，切换路由不遗留 Canvas。

## 不在本次范围内

- 不改写能力区的文案、数据或项目卡片。
- 不新增滚动锁定、音效、鼠标拖拽或手势控制。
- 不为碎片创建物理碰撞、实时破碎或加载外部 3D 模型。
